# CompressionMiddlewareJsonExtensions

> **Status: source removed.** `Middleware/CompressionMiddlewareJsonExtensions.cs` was deleted from the repository in commit `498581e` ("fix: remove junk JsonExtensions files generated by engines"). This page describes the last version of the file (`498581e^`). It does not describe code that is in the current tree. Check the commit before relying on any of the behavior below.

The `CompressionMiddlewareJsonExtensions` class is a static collection of extension methods that convert a `CompressionMiddleware` to and from JSON with System.Text.Json. The type lives in the `RedisCachePatterns.Middleware` namespace. Serialization uses web defaults with camelCase names. The methods do not change the `CompressionMiddleware` instance they are called on.

The methods are not useful in practice. `CompressionMiddleware` has no public properties, so every instance serializes to `{}`, and deserialization fails for every JSON object (see the notes below). The supported encodings and the logger are not part of the JSON.

## API

### ToJson

```csharp
public static string ToJson(this CompressionMiddleware value, bool indented = false, JsonSerializerOptions? options = null)
```

Serializes a `CompressionMiddleware` to a JSON string.

- **value**: The middleware instance to serialize.
- **indented**: `true` to format the JSON for reading; `false` (default) for a compact single-line string. Ignored when `options` is provided.
- **options**: Optional serializer options. When provided, they replace the defaults entirely.
- **Returns**: The JSON representation of the middleware. Always `{}`.
- **Throws**: `ArgumentNullException` when `value` is null.

### FromJson

```csharp
public static CompressionMiddleware? FromJson(string json)
```

Deserializes a JSON string to a `CompressionMiddleware`.

- **json**: The JSON string to deserialize.
- **Returns**: `null` when `json` is empty, only whitespace, or the literal `null`.
- **Throws**: `ArgumentNullException` when `json` is null. `InvalidOperationException` when `json` is a JSON object, including `{}` and malformed input such as `{bad`.

The XML documentation says that a failed read throws `JsonException`. The code does not do this. See the notes below.

### TryFromJson

```csharp
public static bool TryFromJson(string json, out CompressionMiddleware? value)
```

Attempts to deserialize a JSON string. It catches `JsonException` and returns `false` instead of throwing.

- **json**: The JSON string to deserialize.
- **value**: Receives the deserialized middleware instance when the method returns `true`. Set to `null` in every other case.
- **Returns**: `true` if the JSON was read without a `JsonException`; otherwise, `false`.
- **Throws**: Nothing for null, empty, or whitespace input. `InvalidOperationException` for any JSON object. See the notes below.

Null, empty, and whitespace-only input return `false` without throwing. The literal `null` returns `true` with `value` set to `null`. Any JSON object throws `InvalidOperationException`, because the `JsonException` catch does not match it.

## Serialized format

Every `CompressionMiddleware` serializes to:

```json
{}
```

- The class exposes no public properties, so no field is written. The encoding table and the logger are private, so they are not written either.
- The `indented` form is also `{}`.

## Usage

### Serializing a middleware instance

```csharp
using Microsoft.Extensions.Logging;
using RedisCachePatterns.Middleware;

var middleware = new CompressionMiddleware(logger);

string json = middleware.ToJson();                   // "{}"
string pretty = middleware.ToJson(indented: true);   // "{}"
```

### Passing custom serializer options

```csharp
using System.Text.Json;
using RedisCachePatterns.Middleware;

var options = new JsonSerializerOptions { WriteIndented = true };

// indented is ignored here; the supplied options are used as-is
string json = middleware.ToJson(options: options);   // "{}"
```

### Reading a middleware instance

Do not rely on `FromJson` or `TryFromJson` to read a `CompressionMiddleware` from stored JSON. Any JSON object throws `InvalidOperationException`, and `TryFromJson` does not catch it.

```csharp
using RedisCachePatterns.Middleware;

// Throws InvalidOperationException for "{}" and for any other JSON object.
CompressionMiddleware? restored = CompressionMiddlewareJsonExtensions.FromJson("{}");
```

## Notes

*   **The source file no longer exists:** The code this page describes was removed in `498581e`, together with 45 other generated `*JsonExtensions.cs` files. Nothing in the current tree calls these methods, and the file name is not in use. Restore the file from `498581e^` before depending on this API, or delete this page.
*   **Deserialization always fails for objects:** `CompressionMiddleware` has only one constructor, which takes a required `ILogger<CompressionMiddleware>`. System.Text.Json cannot bind that parameter to any property or field, so it fails while preparing the type, before it reads the JSON. The error is `InvalidOperationException` ("Each parameter in the deserialization constructor ... must bind to an object property or field"). It is not a `JsonException`. This happens for valid input (`{}`) and for malformed input (`{bad`) alike.
*   **`FromJson` does not throw `JsonException` for bad JSON:** The XML documentation says that invalid JSON throws `JsonException`. The code catches nothing, so `FromJson` throws `InvalidOperationException` for every object.
*   **`FromJson` returns `null` for empty input:** Unlike `CsvFormatterJsonExtensions.FromJson`, which throws `ArgumentException` for empty input, this method returns `null` for empty and whitespace-only input, because it checks `string.IsNullOrWhiteSpace` before reading.
*   **`TryFromJson` does not return `false` for bad objects:** The method catches `JsonException` only, so the `InvalidOperationException` from the previous note escapes it. It returns `false` only for null, empty, and whitespace input.
*   **`TryFromJson` accepts null without throwing:** The `json` parameter is non-nullable, but the method checks `string.IsNullOrWhiteSpace` first, so a null argument returns `false`. `FromJson` throws `ArgumentNullException` for the same input.
*   **The literal `null` is valid input:** `FromJson("null")` returns `null`. `TryFromJson("null")` returns `true` with `value` set to `null`. Check `value` before using it.
*   **`indented` is ignored when `options` is given:** Without `options`, `ToJson(indented: true)` copies the shared defaults and turns on `WriteIndented`. With `options`, the supplied options are used as-is.
*   **The settings are not round-tripped:** Because `ToJson` writes `{}`, no encoding table or logger survives serialization. Any deserialization that does succeed would produce a new instance with default state, not a copy of the original.
*   **Shared options:** The methods use one shared `JsonSerializerOptions` instance. `ToJson(indented: true)` creates a copy of it for each call. The shared instance is not changed after it is created, so the methods are safe to call from several threads.
*   **Only `CompressionMiddleware` is covered:** The class has one set of methods for `CompressionMiddleware`. It does not handle other middleware types, and it does not handle lists of middleware instances.
*   **Verification:** The behavior above was checked by building the last version of this file (`498581e^`) together with the last version of `Middleware/CompressionMiddleware.cs` in a scratch project outside the repository. The logger was a stub `ILogger<T>`. The serialization results and exception types were observed by running that project on .NET 10. The current `Middleware/CompressionMiddleware.cs` is unchanged since `498581e^`.
