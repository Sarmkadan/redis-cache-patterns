# UserServiceJsonExtensions

> **Status: source removed.** `Services/UserServiceJsonExtensions.cs` was deleted from the repository in commit `498581e` ("fix: remove junk JsonExtensions files generated by engines"). This page describes the last version of the file (`498581e^`). It does not describe code that is in the current tree. Check the commit before relying on any of the behavior below.

The `UserServiceJsonExtensions` class is a static collection of extension methods that convert a `UserService` to and from JSON with System.Text.Json. The type lives in the `RedisCachePatterns.Services` namespace. Serialization uses web defaults with camelCase names. The methods do not change the `UserService` instance they are called on.

The methods are not useful in practice. `UserService` has no public properties, so every instance serializes to `{}`. Its only constructor takes an `IUserRepository`, an `ICacheService`, and an `ILogger<UserService>`, and none of them is written to the JSON. Deserialization cannot succeed for any JSON object, because System.Text.Json cannot bind the constructor parameters to properties (see the notes below). The repository, the cache, the logger, and the cache key constants are never part of the JSON.

The behavior below was taken from reading the removed source. It was not confirmed by compiling or running it.

## API

### ToJson

```csharp
public static string ToJson(this UserService value, bool indented = false)
```

Serializes a `UserService` to a JSON string.

- **value**: The user service instance to serialize.
- **indented**: `true` to format the JSON with indentation; `false` (default) for a compact single-line string.
- **Returns**: The JSON representation of the service. Always `{}`, with or without indentation.
- **Throws**: Nothing for a non-null instance. The XML documentation says `ArgumentNullException` for a null `value`, but the code has no null check. See the notes below.

When `indented` is `true`, the method creates a copy of the shared options with `WriteIndented` set. For an empty object the copy makes no visible difference.

### FromJson

```csharp
public static UserService? FromJson(string json)
```

Deserializes a JSON string to a `UserService`.

- **json**: The JSON string to deserialize.
- **Returns**: `null` when `json` is empty or the literal `null`. Otherwise the result of deserialization.
- **Throws**: `ArgumentNullException` when `json` is null. `InvalidOperationException` for any JSON object, including `{}` and malformed input such as `{bad`.

The XML documentation says that `FromJson` throws `JsonException` for invalid JSON. The code does not do that for object input. See the notes below.

### TryFromJson

```csharp
public static bool TryFromJson(string json, out UserService? value)
```

Attempts to deserialize a JSON string. It catches `JsonException` and returns `false` instead of throwing.

- **json**: The JSON string to deserialize.
- **value**: Receives the deserialized instance when the method returns `true`. Set to `null` in every other case.
- **Returns**: `true` if the JSON was read without a `JsonException`; otherwise, `false`.
- **Throws**: `InvalidOperationException` for any JSON object, including `{}` and `{bad`. It does not throw `ArgumentNullException` for null input. See the notes below.

Null, empty, and the literal `null` input return `false` or `true` as described under Notes. Any JSON object throws `InvalidOperationException`, because the `JsonException` catch does not match it. `TryFromJson` therefore does not act as a "try" method for object input.

## Serialized format

Every `UserService` serializes to:

```json
{}
```

- The class exposes no public properties, so no field is written. The repository, cache, logger, and cache key constants are private, so they are not written either.
- The `indented` form is also `{}`.

## Usage

### Serializing a service instance

```csharp
using RedisCachePatterns.Services;

UserService service = serviceProvider.GetRequiredService<UserService>();

string json = service.ToJson();                 // "{}"
string pretty = service.ToJson(indented: true); // "{}"
```

### Handling input that is not a JSON object

```csharp
using RedisCachePatterns.Services;

if (string.IsNullOrEmpty(stored))
{
    return;
}

// Do not rely on TryFromJson for object input: it throws InvalidOperationException, not returns false.
UserService? restored = UserServiceJsonExtensions.FromJson(stored);
```

Do not use these methods to persist or restore service state. Any object that is not the literal `null` fails to deserialize, and the serialized form carries no state.

## Notes

*   **The source file no longer exists:** The code this page describes was removed in `498581e`. Nothing in the current tree calls these methods, and the file name is not in use. Restore the file from `498581e^` before depending on this API, or delete this page.
*   **Deserialization of any JSON object fails:** `UserService` has a public constructor with parameters and no public properties or parameterless constructor. System.Text.Json therefore throws `InvalidOperationException` ("Each parameter in the deserialization constructor ... must bind to an object property or field") for `{}` and for any other object. This follows from the type's shape and is not confirmed by a run.
*   **`TryFromJson` does not catch `InvalidOperationException`:** Because the `JsonException` catch does not match, object input escapes as an exception even though the method is named `TryFromJson`. Callers that rely on `false` for bad input will get an exception instead.
*   **`TryFromJson(null)` returns `false`:** The method checks `string.IsNullOrEmpty(json)` and returns `false` before any null check. Its XML documentation says it throws `ArgumentNullException` for null, and the code does not do that.
*   **`ToJson(null)` does not throw:** The method has no null check. `JsonSerializer.Serialize` writes the literal `null` for a null reference, so a null `value` returns `"null"`. The XML documentation says it throws `ArgumentNullException`.
*   **`FromJson` and whitespace input:** The method checks only `string.IsNullOrEmpty`, not `string.IsNullOrWhiteSpace`. Whitespace-only input is passed to the deserializer and is not returned as `null`. The exception type for that case was not checked.
*   **The XML documentation does not match the code:** `FromJson` documents a `JsonException` for invalid JSON. The code throws `InvalidOperationException` for object input, as described above.
*   **`TryFromJson` can return `true` with a null value:** The literal `null` is valid JSON, so the method returns `true` and sets `value` to `null`. Check `value` before using it.
*   **Shared options:** The methods use one shared `JsonSerializerOptions` instance. `ToJson(indented: true)` creates a copy of it for each call. The shared instance is not changed after it is created, so the methods are safe to call from several threads.
*   **Only `UserService` is covered:** The class has one set of methods for `UserService`. It does not handle `User`, `IUserRepository`, or lists of users.
