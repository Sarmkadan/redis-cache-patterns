# DistributedLockJsonExtensions

> **Status: source removed.** `Domain/DistributedLockJsonExtensions.cs` was deleted from the repository in commit `498581e` ("fix: remove junk JsonExtensions files generated by engines"). This page describes the last version of the file (`498581e^`). It does not describe code that is in the current tree. Check the commit before relying on any of the behavior below.

The `DistributedLockJsonExtensions` class is a static collection of extension methods that convert a `DistributedLock` to and from JSON with System.Text.Json. The type lives in the `RedisCachePatterns.Domain` namespace. Serialization uses web defaults with camelCase names. The methods do not change the `DistributedLock` instance they are called on.

## API

### ToJson

```csharp
public static string ToJson(this DistributedLock value, bool indented = false)
```

Serializes a `DistributedLock` to a JSON string. When `indented` is `true`, the output is formatted with line breaks and indentation. Otherwise the output is compact.

- **value**: The distributed lock to serialize.
- **indented**: `true` to format the JSON for reading; `false` (default) for a compact single-line string.
- **Returns**: The JSON representation of the lock.
- **Throws**: `ArgumentNullException` when `value` is null.

The computed properties `ExpiresAt`, `IsExpired`, and `TimeRemaining` are written to the output along with the stored state. See the notes below.

### FromJson

```csharp
public static DistributedLock? FromJson(string json)
```

Deserializes a JSON string to a `DistributedLock`. Property names are matched without regard to case.

- **json**: The JSON string to deserialize.
- **Returns**: The deserialized lock. `null` if the JSON cannot be parsed (`JsonException` is caught), if the input is only whitespace, or if the input is the literal `null`.
- **Throws**: `ArgumentNullException` when `json` is null. `ArgumentException` when `json` is an empty string.

### TryFromJson

```csharp
public static bool TryFromJson(string json, out DistributedLock? value)
```

Attempts to deserialize a JSON string. It catches `JsonException` and returns `false` instead of throwing.

- **json**: The JSON string to deserialize.
- **value**: Receives the deserialized lock when the method returns `true`. Set to `null` when the method returns `false`.
- **Returns**: `true` if the JSON was read without a `JsonException`; otherwise, `false`.
- **Throws**: `ArgumentNullException` when `json` is null. `ArgumentException` when `json` is an empty string.

The method returns `false` for a whitespace-only string. It returns `true` with a `null` value when `json` is the literal `null`. The XML documentation says that a whitespace-only string throws `ArgumentException`. The code does not do this. See the notes below.

## Serialized format

A lock created with `new DistributedLock("lock:order:1", "worker-a", TimeSpan.FromSeconds(30))` and serialized before it is acquired produces this output (compact form):

```json
{"key":"lock:order:1","lockValue":"62261bd2-f647-4ac5-bb3c-80cc1212a4d5","acquiredAt":"0001-01-01T00:00:00","duration":"00:00:30","holderIdentifier":"worker-a","retryCount":0,"retryDelay":"00:00:00.1000000","isAcquired":false,"expiresAt":"0001-01-01T00:00:30","isExpired":true,"timeRemaining":"-739913.00:47:59.6506578"}
```

- `key`, `lockValue`, and `holderIdentifier` are strings. `lockValue` is a GUID that the constructor generates.
- `acquiredAt` is a `DateTime` and is written in ISO 8601 format. The value above is the default because the lock has not been acquired.
- `duration` and `retryDelay` are `TimeSpan` values and are written in the standard `[d.]hh:mm:ss[.fffffff]` format.
- `retryCount` is an `int`, and `isAcquired` is a `bool`. Both are always written.
- `expiresAt`, `isExpired`, and `timeRemaining` are computed from the other fields and the current UTC time. They are written as snapshots and are ignored when the JSON is read.
- The methods `Acquire`, `Release`, `CanRenew`, and `RenewLock` are behavior, not state, so they do not appear in the output.

## Usage

### Serializing a lock

```csharp
using RedisCachePatterns.Domain;

var distributedLock = new DistributedLock("lock:order:1", "worker-a", TimeSpan.FromSeconds(30));

string json = distributedLock.ToJson();               // compact
string pretty = distributedLock.ToJson(indented: true);
```

### Reading a lock and handling bad input

```csharp
using RedisCachePatterns.Domain;

if (!DistributedLockJsonExtensions.TryFromJson(storedJson, out var restored) || restored is null)
{
    // Stored value is malformed, whitespace-only, or the literal null
    return;
}

Console.WriteLine(restored.HolderIdentifier);  // worker-a
```

Because `TryFromJson` returns `true` for the literal `null`, check `value` for `null` as well as the return value.

## Notes

*   **The source file no longer exists:** The code this page describes was removed in `498581e`. Nothing in the current tree calls these methods, and the file name is not in use. Restore the file from `498581e^` before depending on this API, or delete this page.
*   **Computed fields are written as snapshots:** `expiresAt`, `isExpired`, and `timeRemaining` are computed when `ToJson` runs. `isExpired` and `timeRemaining` depend on the current UTC time, so the stored text goes stale as soon as it is written. The read path ignores these fields, so they do not affect the restored lock. Do not use them as the source of truth for expiry. Use `AcquiredAt` and `Duration` instead.
*   **Round-trip keeps the stored state:** `key`, `lockValue`, `holderIdentifier`, `acquiredAt`, `duration`, `retryCount`, `retryDelay`, and `isAcquired` are restored. The restored lock is a plain copy and has no connection to any Redis key.
*   **Whitespace handling differs from the XML documentation:** The XML documentation of `FromJson` and `TryFromJson` says that a whitespace-only `json` throws `ArgumentException`. The code only checks for null and empty strings, so a whitespace-only string is passed to the deserializer. `FromJson` returns `null` and `TryFromJson` returns `false`. Callers that rely on the exception will not get it.
*   **Null checks throw `ArgumentNullException`:** Both `FromJson` and `TryFromJson` throw `ArgumentNullException` for a null `json`. `ArgumentNullException` is a subclass of `ArgumentException`, so a `catch (ArgumentException)` handles it too.
*   **`TryFromJson` can return `true` with a null value:** The literal `null` is valid JSON, so the method returns `true` and sets `value` to `null`. Check `value` before using it.
*   **Shared options:** The methods use one shared `JsonSerializerOptions` instance. `ToJson(indented: true)` creates a copy of it for each call. The shared instance is not changed after it is created, so the methods are safe to call from several threads.
*   **Converters and null handling have no effect on this type today:** The options include `JsonStringEnumConverter` and `WhenWritingNull`. `DistributedLock` has no enum properties and no nullable properties, so neither option changes the output.
*   **Only `DistributedLock` is covered:** The class has one set of methods for `DistributedLock`. It does not handle other types, and it does not handle any lists of locks.
