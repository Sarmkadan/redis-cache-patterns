# ProductJsonExtensions

> **Status: source removed.** `Domain/ProductJsonExtensions.cs` was deleted from the repository in commit `498581e` ("fix: remove junk JsonExtensions files generated by engines"). This page describes the last version of the file (`498581e^`). It does not describe code that is in the current tree. Check the commit before relying on any of the behavior below.

The `ProductJsonExtensions` class is a static collection of extension methods that convert a `Product` to and from JSON with System.Text.Json. The type lives in the `RedisCachePatterns.Domain` namespace. Serialization uses web defaults with camelCase names, and null properties are left out of the output. The methods do not change the `Product` instance they are called on.

## API

### ToJson

```csharp
public static string ToJson(this Product value, bool indented = false)
```

Serializes a `Product` to a JSON string. When `indented` is `true`, the output is formatted with line breaks and indentation. Otherwise the output is compact.

- **value**: The product to serialize. Must not be null.
- **indented**: `true` to format the JSON for reading; `false` (default) for a compact single-line string.
- **Returns**: The JSON representation of the product.
- **Throws**: `ArgumentNullException` when `value` is null.

`OrderItems` is marked `[JsonIgnore]` on `Product`, so it is never written. See the notes below.

### FromJson

```csharp
public static Product? FromJson(string json)
```

Deserializes a JSON string to a `Product`. Property names are matched without regard to case.

- **json**: The JSON string to deserialize.
- **Returns**: The deserialized product. `null` if `json` is only whitespace, or if the input is the literal `null`.
- **Throws**: `ArgumentNullException` when `json` is null. `ArgumentException` when `json` is empty (`""`). `JsonException` when `json` is not valid JSON or cannot be deserialized into a `Product`.

The XML documentation lists `ArgumentException` for both null and empty input. For null, the code throws `ArgumentNullException`, which is a subclass of `ArgumentException`. For whitespace, the code returns `null`. See the notes below.

### TryFromJson

```csharp
public static bool TryFromJson(string json, out Product? value)
```

Attempts to deserialize a JSON string. It catches `JsonException` and returns `false` instead of throwing.

- **json**: The JSON string to deserialize. Must not be null or empty.
- **value**: Receives the deserialized product when the method returns `true`. Set to `null` when the method returns `false`.
- **Returns**: `true` if the JSON was read without a `JsonException`; otherwise, `false`.
- **Throws**: `ArgumentNullException` when `json` is null. `ArgumentException` when `json` is empty. Other inputs do not throw.

Only `JsonException` is caught. The argument checks run before the `try` block, so they still throw. Whitespace-only input returns `false`. The literal `null` returns `true` with a `null` value.

## Serialized format

A product created with the following values and serialized in compact form:

```csharp
var product = new Product
{
    Id = 1,
    Name = "Keyboard",
    Description = "Mechanical",
    Sku = "KB-1",
    Price = 49.90m,
    StockQuantity = 5,
    ReorderLevel = 2,
    Category = "Peripherals",
    CreatedAt = new DateTime(2026, 10, 25, 12, 0, 0, DateTimeKind.Utc)
};
```

produces this output:

```json
{"id":1,"name":"Keyboard","description":"Mechanical","sku":"KB-1","price":49.90,"stockQuantity":5,"reorderLevel":2,"category":"Peripherals","isActive":true,"createdAt":"2026-10-25T12:00:00Z","rating":0,"reviewCount":0}
```

- `price` is a `decimal` and is written as a JSON number. It keeps the scale it was set with, so `49.90m` is written as `49.90`.
- `createdAt` is a `DateTime` written in ISO 8601 format. A UTC value ends with `Z`.
- `rating` and `reviewCount` are always written, including `0`.
- `updatedAt` and `imageUrl` are omitted when they are `null`, because the options use `WhenWritingNull`.
- `orderItems` is never written, because the property has `[JsonIgnore]`.
- The `Product` methods `IsLowStock()`, `IsAvailable()`, `UpdateStock()`, `UpdatePrice()`, `UpdateDetails()`, `SetRating()`, `CalculateDiscount()`, and `Deactivate()` are methods, not properties, so they do not appear in the output.

## Usage

### Serializing a product

```csharp
using RedisCachePatterns.Domain;

var product = new Product { Id = 1, Name = "Keyboard", Price = 49.90m, StockQuantity = 5 };

string json = product.ToJson();                // compact
string pretty = product.ToJson(indented: true);
```

### Reading a product and handling bad input

```csharp
using RedisCachePatterns.Domain;

if (!ProductJsonExtensions.TryFromJson(storedJson, out var restored) || restored is null)
{
    // Stored value is malformed, whitespace-only, or the literal null
    return;
}

Console.WriteLine(restored.Name);  // Keyboard
```

`TryFromJson` throws for a null or empty `storedJson`. Check the value before calling it if the stored value can be empty.

Because `TryFromJson` returns `true` for the literal `null`, check `value` for `null` as well as the return value.

## Notes

*   **The source file no longer exists:** The code this page describes was removed in `498581e`. Nothing in the current tree calls these methods, and the file name is not in use. Restore the file from `498581e^` before depending on this API, or delete this page.
*   **`FromJson` and `TryFromJson` throw for null and empty input:** Both use `ArgumentException.ThrowIfNullOrEmpty`. Null throws `ArgumentNullException` and empty throws `ArgumentException`. The XML documentation of `FromJson` says that an empty input returns `null`. The code throws instead. Only whitespace returns `null`.
*   **`TryFromJson` does not catch the argument checks:** Only `JsonException` is caught. A null or empty `json` throws even though the method returns `bool`. Callers that expect `false` for every bad input will get an exception for null or empty strings.
*   **`TryFromJson` can return `true` with a null value:** The literal `null` is valid JSON, so the method returns `true` and sets `value` to `null`. Check `value` before using it.
*   **`OrderItems` is not serialized:** `Product.OrderItems` has `[JsonIgnore]`. The output never contains order items, and the restored product always has an empty `OrderItems` list. Store and load order items through their own serializer if you need them.
*   **Missing properties keep their defaults on read:** Properties that are absent from the JSON keep the values that the `Product` constructor set. For example, `CreatedAt` becomes `DateTime.UtcNow` when `createdAt` is missing, and `IsActive` becomes `true` when `isActive` is missing.
*   **Enum converter is unused:** The options register a `JsonStringEnumConverter`, but `Product` has no enum properties, so it has no effect on the output.
*   **Computed state is not restored:** The methods do not call `UpdateStock`, `UpdatePrice`, or other domain methods. The values are set directly through the public setters. Deserialization does not check the rules those methods enforce, such as non-negative prices or stock.
*   **Shared options:** The methods use one shared `JsonSerializerOptions` instance. `ToJson(indented: true)` creates a copy of it for each call. The shared instance is not changed after it is created, so the methods are safe to call from several threads.
*   **Time zone in `createdAt`:** A `DateTime` with `DateTimeKind.Local` is written with a UTC offset, not `Z`. `Product.CreatedAt` defaults to `DateTime.UtcNow`, so the default output ends in `Z`.
*   **Only `Product` is covered:** The class has one set of methods for `Product`. It does not handle `List<Product>` or other types.
